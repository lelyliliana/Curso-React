## Cómo recorrer una unidad

Lee la lección, abre su laboratorio y predice una salida antes de modificar. El desarrollo sigue los archivos reales y propone un contraste concreto. Intenta la práctica y consulta después su solución. La galería conserva los laboratorios originales; las extensiones resueltas son vistas separadas que puedes comparar sin editar la referencia.

## Del ejemplo a las features

Las unidades 15, 16 y 25 comparten el catálogo; 22 y 30 comparten tareas. Sus App.jsx son entradas pequeñas, no toda la implementación. Sigue estos límites:

| Recorrido | Archivos | Qué comprobar |
|---|---|---|
| Acción de tareas | Tareas → reducer → dominio | Validación, id y ausencia de mutación |
| Guardado | Tareas → almacenamiento → serialización | Revisión cero no escribe; escritura puede fallar |
| Carga remota | Catalogo → useCatalogo → cliente | Fase, categoría, identidad y cleanup |
| Navegación | Entrada → router → galería/proyecto | URL directa, título y foco |

La [extensión de prioridad](../unidad33-taller/ejemplo/prioridad.js) es un módulo puro con migración v1/v2 y pruebas. No está conectada automáticamente al formulario ni al Storage del proyecto base. Úsala para construir esa ampliación de manera explícita, conservando una copia del documento anterior.
