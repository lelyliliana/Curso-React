# Rúbrica del proyecto (100 puntos)

[Enunciado](PRACTICA.md) · [Checklist](CHECKLIST.md) · [Índice](../README.md)

Cada criterio se valora con 20 puntos cuando cumple la evidencia completa; 10 cuando funciona parcialmente y conserva una explicación verificable; 0 cuando está ausente o no permite reproducir lo declarado.

| Criterio | 20 puntos | 10 puntos | 0 puntos |
|---|---|---|---|
| Dominio y estado | CRUD, límites, identidad y vista derivada sin mutaciones | Funciones principales con un límite o transición incompleto | Datos/acciones no corresponden al contrato |
| Efectos y fallos | Limpieza, respuesta vigente y Storage falible documentados | Maneja fallos básicos pero omite una carrera o recuperación | Confunde errores con éxito o pierde datos sin informar |
| Interfaz y acceso | Formularios, nombres, teclado, foco y reflow comprobados | UI utilizable con alguna evidencia de acceso pendiente | Controles esenciales no operables o sin identificación |
| Pruebas y diagnóstico | Casos significativos, build y regresión de un fallo real | Suite básica con evidencia incompleta de flujos | Pruebas inexistentes o no reproducibles |
| Arquitectura y entrega | Dependencias claras, lockfile, README y publicación/limitaciones exactas | Ejecutable con organización o documentación parcial | Otra persona no puede ejecutar o se anuncian capacidades inexistentes |

No se puntúa por cantidad de librerías ni por usar memo en todos los componentes. Una solución alternativa puede obtener la valoración completa si cumple contrato y evidencia. Una URL estática no acredita por sí sola funcionamiento de la API local.
